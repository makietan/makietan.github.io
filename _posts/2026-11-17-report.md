動画ファイルとダウンロード途中の関連ファイルを、誤ってGitにコミットしてしまいました。

作業ディレクトリから削除するだけでは、過去のコミットにデータが残ります。一方、履歴を操作する途中で動画が復元されると、ディスクの空き容量を圧迫します。

そこで今回は、**大容量ファイルの内容を読み書きせず、Gitのツリーとコミット情報だけを書き換える方法**で、ローカル履歴から除去しました。

## 1. 操作対象を絞る

最初に、現在のブランチと作業状態を確認しました。

```bash
git symbolic-ref --short HEAD
git status --porcelain=v1 -uno
```

ステージ済み・未ステージの変更がある場合は、それらを巻き込まないことが重要です。実際の書き換えは、作業ツリーを整理してクリーンにした状態で行いました。

次に、ファイル名に含まれる識別子を使い、追加されたコミットを絞り込みました。

```bash
git log \
  --since='<取り込んだ日付>' \
  --no-renames \
  --diff-filter=A \
  --format='%H %P %s' \
  HEAD -- ':(glob)*<動画の識別子>*'
```

これはコミット情報を調べる操作で、動画の内容を出力するものではありません。

## 2. 書き換える範囲を決める

対象は、最初に動画を追加したコミットから現在のHEADまでとしました。

今回の履歴は、この区間にマージコミットがない直線的な構造でした。書き換え前に、各コミットの親が直前のコミットと一致することを確認しました。

除去対象には、完成した動画だけでなく、分割ダウンロードされた動画とダウンロード管理ファイルも含めました。

## 3. ファイルを復元せずに履歴を書き換える

通常のファイル操作ではなく、次のGitコマンドを組み合わせたスクリプトを使用しました。

| コマンド | 用途 |
|---|---|
| `git cat-file commit` | 元のコミット情報を取得 |
| `git ls-tree -z` | ツリーのエントリを取得 |
| `git mktree -z` | 対象ファイルを除いたツリーを作成 |
| `git hash-object -t commit -w --stdin` | 新しいコミットを保存 |
| `git update-ref` | ブランチの参照先を更新 |

各コミットについて、対象ファイルのエントリだけを除去し、新しいツリーを作成しました。続いて、コミットのツリーIDと親コミットIDを差し替え、後続コミットへ順番につなぎ直しました。

**対象以外のファイルは、既存のオブジェクトをそのまま再利用します。** 動画の展開や再圧縮は行っていません。

今回の対象ファイルはすべてリポジトリ直下にあったため、ルートのツリーだけを更新できました。サブディレクトリ内のファイルを除去する場合は、その階層のツリーも更新します。

## 4. ブランチとインデックスを更新する

新しい履歴を作成した後、元のHEADが変わっていないことを条件に、ブランチの参照先を更新しました。

インデックスも新しいHEADに合わせましたが、作業ファイルを書き換える操作は行いませんでした。

## 5. 動画以外が変わっていないことを検証する

書き換え前後のコミットを対応付け、次の点を検証しました。

- 対象ファイルのエントリが、書き換え区間のすべてのコミットから消えている。
- 対象以外のツリーエントリが一致している。
- コミット数・作者情報・日時・メッセージが保持されている。
- リモート追跡ブランチが変更されていない。
- 作業ツリーがクリーンである。

これで、大容量ファイルを現在のブランチの履歴から除去できました。

## 履歴からの除去と容量回収は別

ここまでの操作では、古いコミットや動画オブジェクトを物理的に削除していません。reflogや別の参照から旧履歴にアクセスできる場合もあります。

つまり、**履歴から消えたことと、ディスク容量が戻ることは別です。**

今回の除去作業では、GCや再圧縮は実施していません。容量回収は、旧履歴の復旧が不要であることと、一時的な空き容量を確認したうえで、別の作業として扱いました。
