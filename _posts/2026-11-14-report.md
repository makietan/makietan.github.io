「履歴を整理」には、**コミットを整える**ことと、**古いデータを削除して容量を回収する**ことの2種類があります。

## コミットを整える
`origin/master` より後のローカルコミットを整理するなら、次です。

```bash
git -c gc.auto=0 -c maintenance.auto=false rebase -i origin/master
```

`-c gc.auto=0 -c maintenance.auto=false` は、rebase中に自動GCやメンテナンスが走らないようにするオプションです。

開いた一覧で、各行の `pick` を変更します。

| 指定 | 操作 |
|---|---|
| `pick` | そのまま残す |
| `reword` | メッセージを変更 |
| `squash` | 直前のコミットにまとめ、メッセージを編集 |
| `fixup` | 直前にまとめ、そのコミットのメッセージを破棄 |
| `drop` | コミットとその変更を除外 |

これはコミットIDを書き換えます。既に共有した履歴には慎重に使い、今回は必要がなければ再度rebaseする必要はありません。

## ディスク容量を回収
今回の動画は現在の履歴から除去済みですが、旧データは残っています。容量回収には次の段階が必要です。

1. 別ブランチやタグが旧履歴を参照していないことを確認する。
2. reflogによる旧履歴の保持を期限切れにする。
3. 不要になったオブジェクトを削除する。

**これはrebaseとは別作業です。** reflogを期限切れにすると復旧手段が減り、通常のGCは再圧縮で一時的な空き容量を必要とします。今回のディスク事情では、`git gc --aggressive` や一括削除を安易に実行すべきではありません。

今回の目的が「残った動画データを消して容量を空ける」なら、必要なのは後者です。
